初学后端

学后端不是背组件，而是理解“什么问题该用哪个组件、它们怎么串起来”。

后端全景地图

层级 定位 代表技术
① 业务与架构层 系统怎么设计和拆 分层架构 / 微服务 / DDD / 单体 vs 分布式
② 框架与编程层 代码怎么写 Java / Spring Boot（Web 框架）/ MyBatis / 分层
③ 中间件层 能力从哪来 MySQL / Redis / MQ / ES / Nacos / Gateway
④ 基础设施层 跑在哪、怎么运维 Linux / Docker / K8s / Nginx / 监控 / CI-CD

  • 注意！分层架构不是全景图里的一个独立层，而是②框架层内部的一种代码组织方式。

  • Web 框架

→ 属于「② 框架与编程层」 它是 写代码的工具

• 它解决的问题： 一个请求进来，怎么写接口处理它

• 它是 具体技术 ，有明确的名字：Spring MVC、Spring Boot

• 不管单体还是微服务，都要用 Web 框架

  • 微服务

    → 属于「① 业务与架构层」

    它是 系统设计的思想 ，不是某个具体框架：

    • 核心思路：把一个大系统，按业务拆成一堆独立的小服务。

    • 它解决的问题： 一个系统要不要拆、怎么拆、拆完怎么协同

    • 它是 架构选择 ，是“单体的另一个选项”

    • 落地时才需要一堆具体工具（Nacos、Gateway 等，那些在③中间件层）

  • 举例
    一个真实系统展开是这样：
    微服务系统 ← ① 架构层（拆成了3个服务）’

    用户服务
    Spring Boot Web 框架 ← ② 框架层（每个服务内部）

    分层：Controller/Service/DAO

    MySQL ← ③ 中间件层

    Docker 部署 ← ④ 基础设施层

    订单服务（同样结构）

    支付服务（同样结构）

    ↑ 服务之间靠 Nacos 发现、Gateway 统一入口 ← ③ 中间件层

分层架构

就是把一个软件系统按职责从上到下切成几层，每层只干自己那摊事，并且 只允许相邻层之间调用 。就像公司里基层员工不直接找老板签字一样。

一句话记忆： 分层 = 每层只做一件事，上下单向调用，靠接口解耦。

  • 最经典的：三层架构 后端开发里最常见的就是这套：

│ 表现层 / Controller 层 │ ← 接收请求、返回响应

│ 业务层 / Service 层 │ ← 核心业务逻辑

│ 数据访问层 / DAO / Mapper │ ← 增删改查数据库

│ 数据库 / 外部资源 │

  • 分层的核心铁律
  1. 只能自上而下调用 ：Controller 可以调 Service，Service 可以调 DAO，但 DAO 不能反过来调 Service ，Controller 也不能跨过 Service 直接调 DAO。
  2. 每层只管自己 ：Controller 不写 SQL，DAO 不做业务判断，Service 不碰 HttpServletRequest。
  3. 层与层之间靠接口通信 ：上层只依赖下层的接口，不关心实现。这样以后换数据库只动 DAO 层。

  • 分层的代价

  • 分层不是免费午餐：

    • 代码变多 ：一个简单的”增删改查”要写 3~4 个类；

    • 数据要层层传递 ：Controller 收到的参数要转成 DTO 传给 Service；

    • 过度设计风险 ：业务很简单还硬拆四层，纯属自找麻烦；

    • 性能开销 ：多一次调用就多一层栈，不过通常可忽略。

  • 几个容易混的
    • 分层架构 ≠ MVC ：MVC 是 UI 层的划分模式（模型/视图/控制器）；分层架构是整体的纵向切分。Web 项目里 MVC 通常只体现在表现层内部。

    • 分层架构 ≠ 微服务 ：微服务是”按业务垂直拆分”（订单服务、用户服务），分层是”按职责水平拆分”。一个订单微服务内部，照样会分层。

    • 四层、五层也常见 ：比如加上”领域层（Domain）”、独立的”基础设施层”，就是 DDD 的经典四层。

生态

“后端生态”说的不是某一个技术，而是 围绕后端开发的一整套技术、工具、框架、服务和社区的总和 。可以类比成“生态系统”这个词的比喻用法：土壤、植物、动物互相支持、彼此依赖。

后端生态包含什么

可以按从核心到外围分四圈来理解：

  1. 第一圈：语言 + 框架（地基）

    • Java ：JDK 版本、Java 语言特性（Lambda、Stream、记录类）

    • 框架 ：Spring、Spring Boot、Spring MVC、MyBatis / MyBatis-Plus

    这一圈就是绝大多数人说的“后端技术栈”主体 第二圈：基础设施（必须碰的中间件） 表格

  2. 第二圈：基础设施（必须碰的中间件）

类别 解决什么
数据库 存业务数据
缓存 加速热点数据、分布式锁
消息队列 削峰、异步、解耦
搜索引擎 全文检索、日志分析
注册中心/配置中心 服务发现、动态配置
网关 统一入口、限流、鉴权

  1. 第三圈：工程化能力（决定你能不能干活）

    • 版本控制 ：Git（你刚在折腾的东西）

    • 构建工具 ：Maven、Gradle

    • 容器化与部署 ：Docker、K8s、Jenkins/GitHub Actions

    • 测试 ：JUnit、Mockito、Postman / Apifox 接口测试

    • 日志与监控 ：Logback、Prometheus + Grafana、SkyWalking（链路追踪）

    • Linux 命令 ：部署一定跑在 Linux 上，ps、grep、tail -f 这类绕不开

  2. 第四圈：工程规范与安全（进阶）

• 接口设计规范（RESTful、统一返回体、错误码）

• 认证授权（JWT、OAuth2、Spring Security） 

• 安全防护（防 SQL 注入、XSS、接口限流防刷、密码加密存储）

• 性能优化（SQL 优化、索引、连接池、JVM 调优） 
 
• 分布式问题（分布式事务、幂等、可靠性投递）

为什么叫“生态”而不是“技术列表” 因为这些东西 不是孤立的 ，它们互相咬合，组合起来才见功力。

学习顺序

  • 学的顺序 ：

先学 ② 框架层 → 用 Spring Boot + MySQL 写出完整单体（阶段1）

再补 ③ 中间件 → Redis / MQ / Linux 部署（阶段2-3）

最后学 ① 架构层 → 微服务拆分（阶段4，且看需求）

②③是能立刻变现的技能，①架构是锦上添花的选择。
